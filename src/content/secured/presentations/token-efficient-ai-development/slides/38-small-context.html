38Structure

Build for small context.

Small, single-purpose files
→A five-line change should touch one small file, not an 800-line module. The agent loads less to act, and hallucinates less.
Clear boundaries (hexagonal)
→Split into domain, usecases, ports and adapters. Dependencies point inward, so the agent reasons about one layer at a time, not the whole graph.
Vertical slices, not layers
→Group by capability, so everything one feature needs (billing, auth, snippets) lives in one folder. The agent opens that slice and ignores the rest of the repo.
The cheapest token is the one you never send. Structure decides how much context a change needs, before you type a single prompt.
