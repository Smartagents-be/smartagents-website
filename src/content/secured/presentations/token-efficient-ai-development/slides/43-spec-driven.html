For bigger work, write the spec first.

01

What it must do, and the acceptance criteria.

02

Architecture, APIs, the files it touches.

03

Tasks

04

Build

Implement one task at a time, review each.

Plan mode is the lightweight version; a spec is the durable one you review, commit, and implement against. Reach for it on big, multi-file features, not one-line diffs.

Tools: GitHub Spec Kit (/specify → /plan → /tasks), Amazon Kiro (requirements / design / tasks), or Claude Code plan mode.
