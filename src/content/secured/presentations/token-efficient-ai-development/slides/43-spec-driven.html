For bigger work, write the spec first.

Reach for it on big, multi-file features, not on one-line diffs.

01 Spec What it must do, and the acceptance criteria.
02 Design The architecture, the APIs, the files it touches.
03 Tasks Break it into small, autonomous steps.
04 Build Implement one task at a time, and review each one.

Plan mode is the lightweight version; a spec is the durable one you review, commit and implement against. Tools: GitHub Spec Kit, Amazon Kiro, or Claude Code plan mode.
